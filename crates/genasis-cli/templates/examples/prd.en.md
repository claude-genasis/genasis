# PRD: I Am a Claude Code Expert

> Status: Draft
> Owner: TBD
> Generated by: `genasis example prd` (ADR-017)
> Target: web app rendered inside the trial-app's left sliding showcase panel

## 1. Overview

A single-page self-assessment quiz that grades the user's Claude Code
knowledge as **Beginner / Intermediate / Advanced**. The app is rendered
inside a mobile-phone frame (rounded chrome, fixed narrow width) so it
is visually unmistakable from the trial-app's own kanban and chat
widgets — the user can see at a glance "this is what the agentic team
built."

After agents finish the build, they invoke `genasis trial publish` to
flip the team's `app_status` to `complete` on the trial-app. From that
point the team's sliding showcase panel reveals this quiz.

## 2. User Story

> As a developer exploring Claude Code for the first time, I want a
> quick way to gauge where I stand — am I a beginner who just learned
> `/help`, or am I writing my own subagents and hooks? Five questions
> are enough to place me, and a fresh restart with new questions tells
> me whether I'm progressing.

## 3. Requirements

### 3.1 Layout — mobile-phone frame

- The app renders inside a "phone chassis" container:
  - Width fixed at ~360px on desktop, full-bleed on mobile.
  - Rounded corners (≥ 32px), dark bezel, subtle drop shadow.
  - Centred horizontally within the parent showcase panel.
- Inside the chassis, three screens swap in place: **start**,
  **question**, **result**.

### 3.2 Start screen

- App title: **"I Am a Claude Code Expert"** (in the active CLI locale).
- One-line description: "Answer 5 questions. We'll tell you your
  level."
- Single primary button: **"Start"** — taps advance to the first
  question.

### 3.3 Question screen

- Question number indicator (e.g. "Question 2 / 5") at the top.
- Question text below.
- Four answer choices rendered as full-width tap targets (radio /
  button hybrid — only one selectable).
- "Next" button activates once an answer is chosen.
- Tapping "Next" advances to the next question; on the 5th, advances
  to the result screen.
- Per-question correctness is recorded but NOT shown until results.

### 3.4 Result screen

- Score expressed as **N / 5 correct**.
- Level label based on score:
  - **0–1 correct → Beginner**
  - **2–3 correct → Intermediate**
  - **4–5 correct → Advanced**
- One-paragraph encouragement tailored to level.
- **"Restart"** button — pulls a fresh random sample of 5 from the
  bank (see §3.5) and returns to the start screen.

### 3.5 Question bank

A static bank of at least 15 questions, tagged by difficulty
(`beginner` / `intermediate` / `advanced`). On `Start` and `Restart`,
the app draws 5 questions weighted to span all three levels (e.g.
2 beginner + 2 intermediate + 1 advanced) so a single session can
discriminate level. The exact sampling distribution is implementation
detail; the constraint is "the same question never appears twice in
one session" and "across two consecutive sessions, ≥ 70% of questions
differ."

Examples of beginner / intermediate / advanced content (the bank
should span these):

- **Beginner**: What does `/clear` do? Which directory holds
  Claude Code settings? How do you switch the active model mid-session?
- **Intermediate**: What is a slash command file structured like?
  How do hooks differ from skills? What is a marker fence in the
  context of `.claude/agents/`?
- **Advanced**: When would you write a subagent vs a skill? How does
  prompt caching interact with the Anthropic SDK's batch API? What
  invariants does the Plane / Mattermost provider trait enforce on
  trial flavor?

(Agents are free to generate their own questions provided they meet
the difficulty intent and cover Claude Code rather than generic
programming.)

## 4. API / Persistence

None. The quiz is fully client-side. Question selection is
deterministic on a per-session seed (the seed itself is random per
session, but reproducible if a future feature wants "share my result").
No login, no storage, no telemetry.

## 5. Trial-app integration (ADR-020 push-to-operator model)

The agentic team builds **a standalone React app under the project's
`app/` subdirectory**, then `genasis push` uploads the static assets
to the operator's trial-app. The operator serves them directly from
`/dev/<team_token>/`, so the demo URL stays live even after the user's
machine sleeps and is reachable from any device.

Required layout (relative to the project root the user created with
`mkdir my-team && cd my-team && genasis init --trial` — standard
Claude project shape):

```
my-team/                       ← cwd / project root
├── .claude/agents/            ← genasis-managed agent definitions
├── .genasis/                  ← daemon state
├── genasis.toml               ← provider + trial config
├── PRD.md                     ← this file
└── app/                       ← frontend scaffolds the React app here
    ├── package.json           # vite + react-ts deps
    ├── vite.config.ts
    ├── index.html
    ├── src/
    │   ├── main.tsx
    │   ├── App.tsx            # mounts QuizApp
    │   ├── components/
    │   │   └── QuizApp.tsx    # the quiz from §3 + §4
    │   └── lib/
    │       └── quiz-bank.ts   # the question bank
    └── dist/                  ← `npm run build` output (genasis push uploads this)
```

Workflow (PM dispatches in order):

1. **frontend** Task — `npm create vite@latest app -- --template
   react-ts --yes` + `(cd app && npm install)` + write
   `app/src/components/QuizApp.tsx` / `app/src/lib/quiz-bank.ts`
   per §3-§4 + `(cd app && npx tsc --noEmit)` typecheck.
2. **devops** Task — `(cd app && npm run build)` produces
   `app/dist/`, verify `[ -f app/dist/index.html ]`, then call
   `genasis push --dir ./app/dist`. The push uploads static assets to
   the trial-app, updates `sim_teams.showcase_pushed_at`, and the
   showcase panel placeholder ("준비중" / "Waiting…") flips into a
   live iframe of the built app.
3. **app_status** flips to `complete` automatically on publish — no
   separate call needed.

Never `npm create vite@latest .` (cwd directly) — it pollutes the
Claude project root with Vite scaffolding and breaks the layout the
user expects. Always scaffold under `app/`.

The legacy v0.5.x flow (`announce_dev_server_url` + localhost iframe)
is retired by ADR-020. The user's laptop no longer needs to host a
dev server, so the demo survives sleep / network changes.

## 6. Acceptance criteria

- Start screen renders within the mobile chassis with the correct
  title in the active locale.
- A full session (Start → 5 questions → Result) completes without
  losing answers.
- Level mapping matches §3.4 exactly (0–1 / 2–3 / 4–5).
- Restart yields a different sample of 5 questions in ≥ 7 of 10
  consecutive restarts (statistical, not strict).
- Restart returns to the start screen, NOT directly into questions.
- Showcase panel toggles open and closed via the LiveBoard button and
  closes on click-outside or Esc.
- For teams whose `app_status` is `NULL` or `'building'`, the panel
  toggle button is disabled (or shows a "Agents still building…"
  hint).

## 7. Non-goals (v1)

- Per-user score history / leaderboards.
- Question editor UI inside the trial-app.
- Sharing results to social media.
- Localising the question bank itself (the bank can be English-only
  in v1; the UI chrome — buttons, labels, level names — must follow
  the active locale).
- Accepting agent-uploaded code. The quiz implementation is fixed.
