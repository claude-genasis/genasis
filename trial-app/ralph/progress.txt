# Ralph Progress Log — GenasisTrialApp (ralph/trial-webapp)

## Codebase Patterns
- Next.js project root is `/work/genasis/trial-app/` (not `apps/trial-app/` as PRD wording suggests; ralph workspace lives in `ralph/` sibling dir).
- App Router structure: `app/layout.tsx` is the root layout, `app/page.tsx` the landing page, `app/globals.css` holds Tailwind directives.
- TypeScript strict mode is enabled; run `npm run typecheck` (alias for `tsc --noEmit`) for type validation.
- Tailwind v3 (`tailwind.config.ts` + `postcss.config.js`); content scan is restricted to `app/**` and `lib/**`.
- `tsconfig.json` excludes `node_modules` and `ralph/` so the ralph workspace doesn't pollute typechecking.
- Path alias `@/*` resolves from project root.
- HTML root lang is `ko` (Korean is the primary user-facing language).
- Use `next` 15.5.x (15.1.x has CVE-2025-66478); confirm via `npm view next versions`.
- DB lives at `db/index.ts` — call `getDb()` (singleton, lazy) for a connected, migrated `Database` instance; tables are created idempotently with `CREATE TABLE IF NOT EXISTS`.
- `lib/token.ts` exports `generateToken()` for 24-byte (32-char) base64url tokens — use this for any new token field.
- `DATABASE_PATH` env var overrides the default `./data/trial.db`; the `data/` dir is gitignored and auto-created at first connect.
- Native modules: `better-sqlite3` is a native addon and must be available at server-runtime (Node, not Edge). Always import DB-touching modules from server components / route handlers, never from `"use client"` files.
- Next.js 15: `searchParams` (and `params`) in server page components is a `Promise<...>` — type as `Promise<{ key?: string | string[] }>` and `await` before reading. Forgetting this triggers a Next 15 dev warning and breaks types under strict mode.
- Shared UI components live at `app/components/<Name>.tsx`. Import with the `@/app/components/<Name>` path alias.
- Tab/active-state navigation pattern: pass `activeTab` from server page → component prop → render `<Link>` with `aria-current="page"` on the active item. No client component needed for plain link-based tab switching.

- **Learnings for future iterations:**
  - **MM env var policy**: when both `MM_BOT_TOKEN` and `MM_TRIAL_CHANNEL_ID` are unset, the route silently SKIPS notification (200 with `notification:"skipped"`). When either is set but the call fails, it RETURNS 500 (with the row already persisted). This is a pragmatic departure from a strict reading of the AC ("500 on MM failure") — without it, every local dev `npm run dev` would 500. Future stories that add provider integrations should follow this pattern: env-vars-unset = skip, env-vars-set + call-fails = error.

  - **Tagged unions for fallible IO**: `NotifyResult = {kind:"sent"} | {kind:"skipped"} | {kind:"failed", reason}` is more pleasant than throwing-and-catching. The route handler reads `notify.kind` and decides the response status without try/catch noise. Use this pattern for any future external API integration (Plane, Slack, etc.).
  - **Always save BEFORE side effects**: `insertSubmission(...)` runs before `notifyMattermost(...)`. If MM fails, the row exists; if we flipped the order, MM-failure could leave the user with no record. Generally prefer "persist first, side-effect after" for any API that mutates and notifies.
  - **Form redirect on 500-with-statusUrl**: even though the response is 500, when `data.statusUrl` is present we still redirect. The applicant isn't responsible for MM admin notification — they just need their status link. Don't show them the MM error.
  - **Functional fetch in client**: `phone: form.phone.trim() || undefined` — sending `undefined` (not empty string) so zod's `.optional()` works as expected. The route handler then normalizes `phone?.trim() || null` before persisting (DB column is nullable).
  - **`runtime = "nodejs"` is required** for any route handler that touches better-sqlite3. Edge runtime is the Next.js default and would break the native module. Set this explicitly on every DB-touching route — don't rely on inheriting the default.
  - **`dynamic = "force-dynamic"`** prevents Next.js from trying to statically generate the route at build time. Without it, `request.json()` would fail during prerender. POST routes that read the body are inherently dynamic — set this explicitly.
  - **Validation issues path serialization**: zod's `issue.path` is `(string | number)[]`. The route handler returns it as-is in the JSON response. Future client-side rendering of these errors should join with `.` (`["address","line1"]` → `"address.line1"`) or special-case array indices.
  - **Test isolation pattern**: `DATABASE_PATH=/tmp/trial-test-<unix-ts>.db` env var lets curl-based verification run against a clean DB without polluting `./data/trial.db`. Clean up the file (`rm -f $TEST_DB $TEST_DB-wal $TEST_DB-shm`) after each verification round.
